Soli's Archive / README Guide

Soli's Archive 프로젝트 정리

이 문서는 Soli's Archive의 전체 구조, PDF OCR 변환 방식, 웹 렌더링 흐름, 앞으로 과목 자료를 추가하는 방법을 한눈에 보기 위한 HTML 설명서입니다.

프로젝트 개요

Soli's Archive는 대학에서 수강한 과목을 학년, 학기, 과목 트리로 정리하고, 각 과목 자료를 웹에서 원본처럼 보면서 검색할 수 있게 만드는 정적 아카이브입니다.

작업 흐름

1
HWP 원본 보관

HWP는 원본 보관용입니다. 웹 변환에는 직접 사용하지 않습니다.

2
PDF로 내보내기

한글/한컴에서 HWP를 PDF로 추출해 assets/pdfs/<학기>/<과목명>/에 저장합니다.

3
과목 데이터 연결

data/courses.json에 sourcePdf 또는 sourcePdfs와 html manifest 경로를 등록합니다.

4
OCR 변환 실행

tools/render_html_pages.py가 페이지 이미지와 OCR 텍스트 JSON을 생성합니다.

5
웹에서 표시

웹 앱이 manifest를 읽고 PDF 이미지 위에 투명 OCR 텍스트 레이어를 얹습니다.

PDF OCR 변환

OCR 변환 결과는 과목별로 아래 파일들을 만듭니다. 

assets/html/<학기>/<과목명>/<course-id>/
├─ page-001.webp        원본처럼 보이는 페이지 이미지
├─ page-001.text.json   OCR 텍스트와 위치 좌표
├─ manifest.json        전체 페이지 정보
└─ index.html           단독 HTML 문서

필요 도구

brew install tesseract tesseract-lang
python3 -m pip install -r requirements.txt

전체 변환

python3 tools/render_html_pages.py --lang kor+eng

특정 과목만 변환

python3 tools/render_html_pages.py --course data-structure-summary --lang kor+eng

GitHub Pages 관리

이 저장소는 .github/workflows/pages.yml을 통해 GitHub Actions 방식으로 배포합니다. main 브랜치에 push되거나, GitHub 웹사이트에서 workflow를 수동 실행하면 새 배포가 만들어집니다.

현재 publish 방식

1
로컬에서 변경 작업

PDF 추가, OCR 변환, data/courses.json 연결을 완료합니다.

2
main 브랜치에 push

push가 완료되면 Deploy static site to GitHub Pages workflow가 자동 실행됩니다.

3
Actions 완료 확인

GitHub 저장소의 Actions 탭에서 workflow가 초록색 체크로 끝났는지 확인합니다.

4
사이트 접속

배포가 끝나면 https://solishim.github.io/Univ-Archive/에서 최신 사이트를 확인합니다.

GitHub 웹사이트에서 unpublish 하는 방법

  1. GitHub에서 SoliShim/Univ-Archive 저장소로 들어갑니다.
  2. Settings 탭을 엽니다.
  3. 왼쪽 메뉴의 Pages로 이동합니다.
  4. Your site is live at 문구 오른쪽의 점 세 개 메뉴를 누릅니다.
  5. Unpublish site를 선택합니다.

unpublish는 현재 배포본만 내리는 동작입니다. 저장소 파일, workflow, 설정 자체를 삭제하지는 않습니다.

unpublish 후 다시 publish 하는 방법

  1. GitHub 저장소의 Actions 탭으로 이동합니다.
  2. Deploy static site to GitHub Pages workflow를 선택합니다.
  3. Run workflow를 누르고 브랜치는 main으로 둔 뒤 실행합니다.
  4. workflow가 성공하면 새 Pages 배포가 만들어지고 사이트가 다시 열립니다.

같은 효과를 내는 다른 방법은 아무 변경 사항이나 main에 새로 push하는 것입니다. 이 저장소는 push를 트리거로 Pages 배포가 다시 실행되기 때문입니다.

주의할 점

  • GitHub Pages를 unpublish해도 public 저장소의 파일 자체가 비공개가 되지는 않습니다.
  • 자료 노출을 막고 싶다면 사이트 publish 상태와 별개로 저장소 공개 범위, 자료 저장 위치를 같이 관리해야 합니다.
  • Settings의 Pages source를 바꾸는 방식보다, 이 프로젝트에서는 Actions workflow를 다시 실행하는 방식이 가장 안전합니다.

핵심 파일 역할

index.html 트리형 아카이브 앱 진입점입니다.
course.html 이전 과목 상세 URL을 새 URL로 넘기는 호환용 페이지입니다.
data/courses.json 학년, 학기, 과목, 교수, PDF, HTML manifest 경로를 관리합니다.
js/archive.js 트리 탐색, 과목 상세 렌더링, OCR 문서 검색을 담당합니다.
styles.css 앱 UI, 문서 뷰어, floating 검색바 스타일을 담당합니다.
tools/render_html_pages.py PDF를 페이지 이미지와 OCR 텍스트 레이어로 변환합니다.
